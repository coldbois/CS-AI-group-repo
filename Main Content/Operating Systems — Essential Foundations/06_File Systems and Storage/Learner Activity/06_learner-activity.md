# Try it: Path Treasure Hunt (1.6)

**Time:** 15 min · **Group:** pairs · **You need:** paper; any computer (optional) · Study Guide pp. 37–38

**Goal:** practise reading paths, and see why backups matter.

## Prepare

Use the folder tree in Figure 1.6a on the [topic page](../Main%20Theory/06_main-theory.md):

```
C:\
├── Users
│   └── Sam
│       ├── Documents
│       └── Pictures
│           └── selfie.jpg
└── Program Files
```

Optional: open File Explorer (Windows) or Finder (Mac).

## Steps

1. Write the full path to `selfie.jpg`.
2. Your partner names a made-up file and its folder (for example `essay.docx` in Documents). Write its path. Swap roles twice.
3. On a real computer, find one file and copy its path. Windows: hold **Shift**, right-click the file → *Copy as path*. Mac: right-click, hold **Option** → *Copy as Pathname*.
4. **Story time:** Sam's only copy of an essay is on a laptop that falls into a pool. Design a 3-step backup plan so this can't ruin Sam's week again.

## Record

- Your paths. Check each `\` step against the tree.
- Your 3-step backup plan.

## Reflect

- Why can't two files in the same folder have the same name?
- Why is a backup on the same laptop not enough?

## Check it: expected results

- `selfie.jpg` → `C:\Users\Sam\Pictures\selfie.jpg`
- `essay.docx` in Documents → `C:\Users\Sam\Documents\essay.docx`
- A copied Windows path appears in quotes, for example `"C:\Users\Sam\Downloads\notes.pdf"`.
- Two files with the same name in one folder would have the same address, so the OS couldn't tell them apart.
- A good plan keeps a copy **somewhere else**: a USB drive, an external disk or a trusted cloud service, and makes copies regularly (not once). The **3-2-1 rule** is a good target: 3 copies, 2 kinds of storage, 1 off-site.
